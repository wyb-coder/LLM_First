# AMR-SELOR 下一阶段实施计划

> **背景**：基线实验已完成，Test Acc 63.69%，ROC-AUC 0.7058。核心问题已暴露：
>
> - 三元组解释重复（已修复推理逻辑）
> - 三元组数量爆炸（8 万+），大量无区分度
> - 未见三元组无法泛化

---

## 当前问题诊断

| 问题          | 现象               | 根因                       |
| ------------- | ------------------ | -------------------------- |
| CE 精度天花板 | ~75%               | 8 万三元组太稀疏，统计失效 |
| 测试集泛化差  | 大量样本 OOV       | 未见三元组无 embedding     |
| 解释质量低    | 功能性三元组被选中 | 无区分度过滤               |

---

## 实施计划

### Phase 1：情感区分度过滤（P0+）

**目标**：将三元组词表从 8 万 压缩到 ~5000，保留与标签显著相关的

| 任务                 | 说明                       | 落点                        |
| -------------------- | -------------------------- | --------------------------- |
| 卡方检验过滤         | 保留 p < 0.05 的三元组     | `build_triple_pool.py` 新增 |
| TF-IDF 加权          | 降低高频无区分度三元组权重 | 同上                        |
| 重新生成 true_matrix | 基于过滤后词表             | Stage 2 重跑                |
| 重新预训练 CE        | 更稠密的统计               | Stage 3 重跑                |

**预期收益**：CE 精度提升至 85%+，模型天花板打开

**细化与补充**：
- 过滤阈值：卡方显著性 p < 0.05；同时要求最小文档频率（如 df ≥ 5）以抑制偶发高卡方；可按正/负类分别取 top_k（默认 5000）。
- TF-IDF：使用子线性 TF 和 L2 归一化；对停用关系或超高频三元组施加额外降权（阈值可配）。
- 兼容性开关：`--filter_method none/chi2/tfidf`，默认 `chi2`，保留 `--top_k`；若需要验证旧流程，可设为 `none`。
- 产出与版本：过滤后词表与 true_matrix 按版本号落盘（示例 `result/triples/filtered.v1/triple_vocab.json`、`true_matrix.npz`），日志记录前后规模、保留率与每类 top_k 取值。
- 监控：运行时打印三元组保留数、被滤原因统计（高频、低频、低卡方），便于调参。

---

### Phase 2：三元组文本编码器（P1）

**目标**：让模型能处理未见三元组

| 任务                | 说明                               | 落点                           |
| ------------------- | ---------------------------------- | ------------------------------ |
| Triple Text Encoder | 用 DistilBERT 编码 `head rel tail` | 新增 `utils/triple_encoder.py` |
| 替换查表逻辑        | `embedding = encoder(triple_text)` | `amr_selor.py` 修改            |
| 推理时实时编码      | 无需预计算 embedding table         | `inference_amr_selor.py` 修改  |

**预期收益**：

- 测试集 OOV 问题解决
- 语义相近三元组自动聚类（如 `staff helpful` ≈ `waiter friendly`）

**细化与补充**：
- 模型参数：可配置 checkpoint（默认 `distilbert-base-uncased`）、最大长度（拼接 `head [SEP] rel [SEP] tail`）、池化方式（CLS/mean）。
- 性能：启用半精度/量化可选；训练时可缓存常见三元组 embedding，推理时用 LRU 缓存减少重复编码。
- 回退策略：对已存在的三元组仍可选择查表或编码，提供 `--triple_embedding_mode table/encoder/hybrid`；hybrid 模式优先查表，缺失时调用 encoder。
- 接口改动：`amr_selor.py` 接收 encoder 句柄与 tokenizer，移除对固定 `triple_emb_table` 的强依赖；`inference_amr_selor.py` 支持批量编码与并行度参数以加速推理。
- 产出管理：编码器配置与权重保存到 `result/triple_encoder/`，版本号与 Phase 1 过滤版本对齐便于复现实验。

### Phase 3：可选增强

| 优先级 | 任务                      | 触发条件              |
| ------ | ------------------------- | --------------------- |
| P1     | 指针网络选择器            | 基线选择质量不佳      |
| P1     | 组合式 Head/Rel/Tail 嵌入 | Text Encoder 成本过高 |
| P2     | 联合训练（解除 CE 冻结）  | 基线稳定后            |
| P2     | 复述鲁棒性评测            | 需验证解释一致性      |

**细化与补充（优先挑一到两个验证）**：
- 指针网络：替换或辅助手工打分选择器，重点验证对长文本与高冗余三元组的选取质量提升。
- 组合式嵌入：独立编码 Head/Rel/Tail 并组合，可与文本编码器做轻量对比，降低推理成本。
- 联合训练：解冻 CE 后，监控过拟合风险，必要时增加 dropout / weight decay；记录 CE 与主任务双指标曲线。
- 复述鲁棒性：对三元组文字进行同义改写，检查解释一致性；增加简单模板或回译扰动。

## SPRING 三元组抽取增强（适用于上游 AMR）

**目标**：减少功能性/噪声三元组，提升下游区分度。

- 关系筛选：建立关系白名单/黑名单（如过滤标点、对齐占位符），可配置文件驱动。
- 置信度与启发式：用分数或启发式（节点度、长度）过滤低置信边；裁剪过长尾的节点文本，统一大小写与空白。
- 去重与上限：同一文本出现的重复三元组去重；按文档限制三元组数量上限，优先保留高置信或高 TF-IDF 的。
- 统计与日志：输出每批三元组的均值/中位数长度、关系分布、过滤原因分布，便于回溯。
- 文件落点：过滤后的三元组存入版本化目录（示例 `result/spring_triples/filtered.v1/`），与 Stage 2 过滤版本对应。

## 实施顺序

```
Phase 1 (当前)
└─> 卡方过滤 + TF-IDF → 压缩词表 → 重跑 Stage 2-5
    ├─ 如果 Acc > 70%：成功，进入 Phase 3 可选增强
    └─ 如果 Acc ≤ 70%：立即进入 Phase 2

Phase 2 (备用)
└─> Triple Text Encoder → 解决泛化问题 → 重跑 Stage 4-5
```
