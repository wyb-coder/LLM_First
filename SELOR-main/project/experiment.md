### Experiment 1

#### Do

- 段落级输入 + Max_length(2) 句子输入
- 选取频率 >= 5 的三元组

#### Note

- 分两大模块 ==> 前件估计器、后件估计器
- 后件估计器：先行训练，先通过某种方法提取出原子后，训练`原子 ==> 情感分类标签`的*NN*
  - 后件估计器 == 神经结果估计器，给定规则，判断由此规则 ==> *y = Positive*的概率，以及`这个规则覆盖了多少数据`(需要暴力计算？)
  - *Train*时，前件估计器还不存在，无从预先了解原子的"正确"采样方法，因此，采用统计学上的暴力采样。对于任意规则$\alpha$，其真实概率可以通过扫描整个数据集计算出来。
  - 此外，输入的不是孤立的词汇，是*`Embedding`*，这天然的就让输入数据具有"泛化性" <==> 距离相近的词汇其*Embedding*编码同样相近。
  - ==训练一个`拟合统计规律`的神经网络，其正确性来源于全量数据的统计事实，泛化性来自于*Embedding*空间==
- 前件估计器：在后件估计器训练好后，训练由`文本 ==> 原子`的*NN*，学习如何找出正确原子。

  - BERT 提取输入*x*的特征向量，再使用*`GRU`*`逐步`产生规则。
  - 前件估计器通过后件估计器的反馈更新优化网络。最开始是纯粹的瞎选。
  - 为什么需要：训练后件估计器时是全局扫描，显然太慢了

- 前件估计器仍被需要，因为==*AMR*解析出来的是"全量信息"，里面包含大量噪音和无关事实==

  - 新·前件估计器，需要*`Attention`*`选择带有情感的语义信息`

- 三元组是无限的、动态的，无法直接训练*Emdedding*，使用`语义编码`解决

#### Question

- Stage 1-2
  - AMR 是在每个段落中选取的最长句子，因此，现在一整段 <==> 三元组列表，实际上是这两个句子的情感，但凡出现整段与句子情感颠倒，会出现极大影响。
  - AMR 三元组非常具体(如 (_food, :domain, bad-07_))。如果测试集中出现了一个训练集中没见过的三元组变体(例如谓词稍微不同)，CE 能否泛化？
    - *Embedding*方式，附加的待办的`语义编码`
  - AMR 解析出的三元组有些是“功能性”的，有些是“语义性”的。如果提取出的三元组全是(I, :ARG0-of, say-01)这种无情感倾向的废话，模型性能会崩塌。
    - 建议：三元组过滤规则(_extract_triples.py_)需要精细打磨，甚至需要一个基于*TF-IDF*或卡方检验的筛选器，只保留那些具有区分度的三元组。
- Stage 3
  - 核心问题：==三元组稀疏性导致无法复现原 SELOR 的"统计回归"训练方式==
    - 原 SELOR：随机采样 4 个原子组合 → 覆盖数百~数千样本 → 统计概率可靠
    - AMR-SELOR：随机采样 3 个三元组 → 几乎不可能共现 → 100 万次采样找到 0 个有效组合
  - 解决方案（临时）：从样本内部采样三元组组合
    - 保证每个组合至少覆盖 1 个样本（采样来源样本）
    - 采样效率 43%（目标 5 万，实际 2.1 万），平均覆盖约 13 个样本
  - 训练结果：_Val_MAE = 0.20_，_ArgmaxAcc = 77-81%_
    - 与原 SELOR 相比偏低（原版估计*MAE~0.05*，_Acc~85%_）
    - 但作为基线可接受，先继续 Stage4
  - 待优化方向：
    - 降低`min_coverage`到 1，增加样本多样性
    - 使用粗粒度三元组（如只用*rel+tail*）增加复用率
    - *TF-IDF*筛选高区分度三元组
